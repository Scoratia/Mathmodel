# 复现与取用

## 只阅读、引用现有材料

无需安装任何库。GitHub可直接查看Markdown、图片和CSV；LaTeX连同figures目录下载后可在已有XeLaTeX环境编译。此稿未编译成PDF，不与仓库既有论文PDF混淆。

| 字段/文件 | 含义与单位 |
|---|---|
| id | 情景主键；不得按行号匹配 |
| task / question | 扩展实验编号 / 原题问题编号 |
| moving_radius / eps_final | 是否使用收缩曲线 / 最终非仿射参数 |
| boundary_norm | 当前或初始干密度定义 |
| perturb_kind / logD_delta | 扰动窗口 / 对数倍率幅度 |
| region_width / C_cut / C_smooth | 材料坐标区域宽度 / 含水率阈值 / 平滑宽度 |
| tcritical_s / tmean_s / tail_s | 全域终点 / 平均终点 / 二者差，秒 |
| mass_audit_rel | 保存时间点的通量积分残差，含采样误差 |
| empirical_dry_mass_ratio_end | 经验湿密度反算干质量除以守恒干质量；不是实际质量变化 |
| task2_q3_q4_matched.csv | 事后45组配对，单位小时，正差表示Q4更快 |
| profile_summary.csv | 原始轨迹的诊断汇总；profile_path为归档位置，不是本目录现存文件 |

原配对表的delta是候选减参照，与新增Q3减Q4方向不同。空白表示不可用，不能一概填0。完整NPZ轨迹未放入轻量专题；重新求解才会得到profiles。

## 只重新汇总或绘制三张图

以下命令供使用者在已选择的工作环境执行。本次发布没有执行Python或重新计算。先从本专题目录出发，选择新的输出路径；不要将复算结果写入data或figures。

```bash
# 当前目录：专题分析/GPU结构与扩散实验_20260912
STUDY_DIR="$PWD"
REPRO_DIR="$STUDY_DIR/reproductions/$(date +%Y%m%d_%H%M%S)"
mkdir -p "$REPRO_DIR"
python -m venv "$REPRO_DIR/env"
source "$REPRO_DIR/env/bin/activate"
export TMPDIR="$REPRO_DIR/tmp"
export XDG_CACHE_HOME="$REPRO_DIR/cache"
export MPLCONFIGDIR="$REPRO_DIR/cache/matplotlib"
export PIP_CACHE_DIR="$REPRO_DIR/cache/pip"
export PYTHONPYCACHEPREFIX="$REPRO_DIR/cache/pycache"
mkdir -p "$TMPDIR" "$MPLCONFIGDIR" "$PIP_CACHE_DIR"
python -m pip install -r "$STUDY_DIR/source/requirements-server-base.txt"
python "$STUDY_DIR/source/analyze.py" "$STUDY_DIR/data/summary.csv" \
  --cases "$STUDY_DIR/data/cases_requested.json" \
  --output "$REPRO_DIR/analysis" --figures "$REPRO_DIR/figures"
```

该模式不求解PDE、不需要CuPy。未传入原始profiles，因此不会重新验证轨迹级诊断；原有profile_summary.csv不由这一命令重建。


## 重新计算107个情景

在Linux NVIDIA服务器上使用独立环境及新的工作目录。原实测Python 3.12.14、CuPy14.2.0、FP64；实际依赖见verification/environment_freeze.txt。CUDA12安装清单在source/requirements-cuda12.txt，驱动与运行库兼容性须按所用机器确认。

激活适合该服务器的环境后，从source目录运行；以下变量接续上节，仅表示使用者自行选择的工作目录，不包含个人服务器账号：

```bash
python -m pip install -r "$STUDY_DIR/source/requirements-cuda12.txt"
cd "$STUDY_DIR/source"
nvidia-smi --query-gpu=index,uuid,memory.used,memory.free,utilization.gpu --format=csv
read -r -p '输入刚确认空闲的物理GPU编号: ' PHYSICAL_GPU
export PHYSICAL_GPU CUDA_DEVICE_ORDER=PCI_BUS_ID
export CUDA_VISIBLE_DEVICES="$(nvidia-smi -i "$PHYSICAL_GPU" --query-gpu=uuid --format=csv,noheader)"
export CUPY_CACHE_DIR="$REPRO_DIR/cache/cupy" CUDA_CACHE_PATH="$REPRO_DIR/cache/cuda"
export OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 MKL_NUM_THREADS=1
mkdir -p "$CUPY_CACHE_DIR" "$CUDA_CACHE_PATH"
printf 'physical=%s visible=%s\n' "$PHYSICAL_GPU" "$CUDA_VISIBLE_DEVICES"
test -n "$CUDA_VISIBLE_DEVICES" && nvidia-smi -i "$PHYSICAL_GPU"
python validate_gpu.py --backend cupy --N 320 --output "$REPRO_DIR/validation"
```

仅当退出码0且validation_report.json中passed和cuda_executed均为true时启动。此检查不是空间或实验验证。

```bash
(
  set -o noclobber
  nohup env PYTHONUNBUFFERED=1 timeout --signal=TERM --kill-after=60 14400s \
    python run.py --backend cupy --suite full --N 320 --batch-size 16 \
    --output "$REPRO_DIR/results" > "$REPRO_DIR/compute.log" 2>&1 < /dev/null &
)
tail -f "$REPRO_DIR/compute.log" | stdbuf -oL tr '\r' '\n'
```

该源快照会在求解结束后生成基础分析；要生成完整轨迹诊断和图片，再运行analyze.py并指定新目录及`--profile-dir "$REPRO_DIR/results/profiles"`。计算已经完成而分析失败时优先恢复分析，不直接重算。

长任务应在启动和加载后检查实际Python PID的/proc/PID/environ及nvidia-smi进程表，确认所选UUID。不得终止其他用户进程。每次重连重新声明路径、环境和GPU。上面的4小时是计算预算，不含先前验收；原发布运行的4小时入口预算则包含验收，二者应区分。
